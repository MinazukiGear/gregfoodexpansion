# M1′ 内容运行时接入与首条食物链

状态：手工首批记录；LV 后续批已接入，见 [LV 工坊说明](lv-workshops.md)。M1′ 总闸门仍未完成。2026-09-12。

## 本批范围

- 内容表驱动注册作物主产物、基料、味型、动物分割品与独立菜品 Item。
- 原版鸡蛋、生鸡肉和生牛肉通过别名引用原版物品，不重复注册。
- 首批可种植内容为番茄、大葱。野生变体与栽培变体共用方块；其他作物的种植机制后续接入。
- 首道可食用菜为番茄鸡蛋面；其他菜品仅有登记物品，提示“菜谱待开放”，不计入实装覆盖。
- 陶罐支持四格逐个投料、篝火加热、加水、取餐与存档。常温发酵和机器替代配方随后续批次实现。
- 未接入品位、增益、SoL 多样性乘数及 LV 机器配方。本批不宣称完成 M1′。

## 生存操作

1. 在新生成的平原、向日葵平原或森林中寻找野生番茄和大葱，打破可获得主产物和种子。
   开垦耕地后种植；成熟作物掉落一份主产物和两粒种子，可持续扩种。已有区块需向外探索。
2. 两块圆石 + 木棍合成研钵；三根木棍合成擀面杖；燧石 + 木棍合成菜刀。
3. 空碗对水源使用得到一碗水；小麦 + 研钵 → 面粉；面粉 + 一碗水 → 面团（返空碗）；
   面团 + 擀面杖 + 菜刀 → 面条。工具每次加工损耗一点耐久。
4. 五个黏土球合成未烧制陶罐，经熔炉烧制得到陶罐；放在点燃的篝火正上方。
5. 依次向陶罐投入一份面条、一个番茄、一枚原版鸡蛋、一份大葱，再加入两碗水。
   投料顺序不限；加水返还空碗；潜行空手使用可取回最后一份未熟食材。
6. 加热 60 秒得到两份番茄鸡蛋面，使用空碗逐份盛取。每份恢复 5 点饥饿值，正常进食后返碗。

时间按加载中的游戏刻累计；熄火或缺水暂停，食材变化重置进度。
打破陶罐退回未熟食材，水与尚未盛出的熟食洒落，不凭空生成容器。
本批不提供漏斗/流体管自动输入。

上述耐久 128、1200 刻、每锅 2 份、营养 5 / 饱和系数 0.5、野生生成频率均为首批草案，
三档一致，不接入难度系统。作物外观及工具图标为管线/原版占位资产，待美术批次替换。

## 数据与生成

- `content/gameplay.json`：当前可种植作物、工作台配方、已开放陶罠菜及数值。
- `content/vanilla-links/*.json`：原版物品引用和旧配料引用别名。当前只接入首链所需材料，
  不等同于已完成作物设计中的 11 种原版接链。
- 陶罐投料从对应矩阵行的主料、辅料和味型读取，不重复维护另一份食材清单。
- 普通内容运行时注册使用 Forge DeferredRegister；GT 机器继续沿用现有 Registrate。
- `runData` 生成模型、方块状态、配方、配方解锁、战利品、标签、世界生成、三语和模板贴图。
  贴图纳入 datagen 缓存，重复生成会保留有效贴图并清理过期产物。
- `generateTextures` 保留为独立美术迭代入口；生成产物随源码入库。

## 校验与后续闸门

lint 分别报告“表引用覆盖”和“已实现手工获取链覆盖”，后者要求菜品已开放并能递归追溯到
原版材料、已开放作物和真实手工配方。该静态审计仍需游戏验证，不替代 M1′ 验收。
当前 8 道开发样本尚不足正式闸门要求的 100 道。

专用服务器测试使用 `src/gametest/` 独立源集，不打入发布 JAR；运行目录是 `build/gametest/`，
不会改动开发客户端存档。执行 `gradlew runGameTestServer` 可检查注册、工作台链、工具与容器返还、
陶罐加热与存档、实际服务端 ticker、错误配方、种植掉落和野生生成。

客户端自动冒烟命令为 `gradlew runClient -PgameplaySmoke`：使用 `build/client-smoke/`，
在启动资源加载完成后检查所有首批物品模型、贴图与作物方块状态，随后自动退出；该检查排除 EMI、
Modern UI 等可选客户端工具，不修改原开发客户端存档，也不代替人工体验验收。
已修复三台既有机器缺少 Registrate 事件监听的问题，并为测试启动失败的零退出码增加完成标记闸门。

LV 压延段、煮段及本菜机器升级已由后续批接入，见 [LV 工坊说明](lv-workshops.md)。下一批扩展作物、其他菜谱和发酵。
正式 M1′ 放行仍需固定 100 道样本、至少 50% 可达率（目标 75%）、完整客户端冒烟及零 lint error。
