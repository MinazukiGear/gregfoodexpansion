# 隧道式烤炉(Tunnel Oven)

> **本文档记录 GregFood Expansion 隧道式烤炉(烘焙工业化大型多方块)的当前设计。** 经讨论定案的内容标注 **[已定案]**,本文新增细节与全部平衡数值标注 **[草案]/[待定]**。尚未定案的内容集中列在文末。
>
> 决议来源:2026-09-07 专项讨论——隧道式可变长度、**并行数较段数适当增大**、**三档炉温**、电路 5=烤(复用 `cooking` 类型)、结构克制(单一外壳+标准仓室)、**烘焙品 SKU 清单后续决定**、**全部具体数值待实机定案且预热时长显著拉长**。

## 1. 定位与范围

**定位**:烘焙工业化的量产端。与通用烹饪机(电路 5=烤)共享同一配方集,以可变长度换取并行吞吐;炉温系统给"批量生产"真实的预热成本。

**非目标**:装配类配方(中央厨房);发酵/熏制/腌制(支柱 C/D 专项);燃气燃烧加热(走标准 EU 能量仓)。

## 2. 注册与命名 [已定案]

| 项 | 约定 |
| --- | --- |
| 控制器 id | `tunnel_oven`,中文"隧道式烤炉" |
| 结构块 | `tunnel_oven_casing` 烤炉外壳(**仅此 1 种**) |
| 配方类型 | 复用 `gregfoodexpansion:cooking`,**仅执行电路 5(烤)配方** |
| 代码包 | `net.mgear.gregfoodexpansion.baking` |
| 电压 | 多方块**无 tier 变体**(GT 惯例),能量接收上限 EV(2048) [草案] |

## 3. 多方块结构 [框架已定案,尺寸草案]

- **隧道式可变长度**:内腔截面固定(宽 3 × 高 3),长度 **3–9 段**可变,控制器位于进料端;
- 仓室全部复用 GTCEu 标准(输入/输出总线、能量仓),**不做专属仓室**;
- 外观:端部视窗、排气口为外壳贴图细节(视窗传送带动画后置,见尚待定案);
- 结构检测按进料端朝向逐段校验,断段即不成形。

## 4. 炉温系统 [三档已定案,数值待定]

**三档炉温 [已定案]**,名义温度为风味口径(非物理模拟):

| 档位 | 名义温度 | 典型用途 |
| --- | --- | --- |
| 低温 | ~160 °C | 蛋糕、舒芙蕾类 |
| 标准 | ~190 °C | 面包、吐司、甜面包 |
| 高温 | ~230 °C | 披萨、脆底类 |

- 配方要求指定档位;**升温 = 预热**:集中耗能,耗时随目标档位递增,且**显著长于单批烘烤时长**(决议:预热拉长)——换档与冷启动都有真实成本,批量生产才有回报;
- 保温期间低 EU 维持;停机缓慢降温(温度按 tick 衰减),重开需重新预热;
- 温度状态机数据对 Jade 暴露(显示当前档位/升温进度)。

## 5. 并行 [机制已定案,数值待定]

**并行数随长度增长,较段数适当增大 [已定案]**。基准结构:**并行数 = 段数 × 2**(3 段起步 6 并行,9 段满载 18 并行),具体倍率为实机平衡项(待定)。

并行执行遵循 GTCEu 惯例:一次运行处理 N 份配方输入,N 倍产出,N 倍 EU 消耗,单批时长不变。

## 6. 配方体系 [归属已定案,清单后续决定]

- 复用 `cooking` 类型,**仅接受电路 5 配方**——烘焙配方一份定义,通用烹饪机(电路 5)小批量可烤,烤炉并行量产,**零重复**(与中央厨房同构);
- 与 GTCEu 既有面包链**共存不抢注**:面团/面包等原配方保留,烤炉新增自己的烘焙配方;
- 冲压机床"面团+可可豆→曲奇"先例保留不迁移;
- 首批烘焙品 SKU(候选:面包、吐司、甜面包、蛋糕、水果派、披萨等,约 8–10 个)**后续专项定案**——披萨作为产业链汇合展示位候选(面皮←压延、番茄酱←炒模式、芝士碎←切配)。

## 7. 数值 [全部待定]

按决议,**所有具体平衡数值待实机定案**,仅保留结构关系:

1. 烘焙配方的 EU/t 与单批时长均**高于**通用烹饪机小批量烤,由并行倍数取得吞吐优势;
2. 预热:能耗集中、耗时随档位递增且显著长于单批烘烤(决议);
3. 保温:低 EU 维持(相对烘烤功耗);
4. 并行:N 倍 EU/N 倍产出、时长不变;
5. 能量接收上限 EV(2048)。

## 8. GUI 与资产 [草案]

- 控制器 GUI:炉温档位显示、预热进度、并行数、配方进度;
- 贴图:外壳 1–2 张(含端部/视窗变体)+ 控制器正面;量级 ≤5 张;
- 音效/粒子(排气、完成提示):实现期补充。
