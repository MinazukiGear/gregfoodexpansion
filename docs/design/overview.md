# Greg Food Expansion 设计总纲(Design Overview)

> **状态:设计 v2.0 · 方向已定案(全量重置版)** — 2026-09-09
>
> 本文档集是对 2026-09-07 旧版设计(农业+食品双端工业化、菜肴 70 道、切配机/通用烹饪机单方块体系)的
> **全量推倒重写**。旧版全部文档、内容代码与贴图已删除(git 历史可考古)。
> 本文档集为准:凡与旧版表述冲突之处,以本文档集为准。
> 各专项文档中未标注"已定案"的数值均为草案,实装期按文档收口制逐项定案。

## 1. 定位与问题定义

**模组定位**:基于 GTCEu Modern 的**生物工业主线**模组——作物、畜牧、发酵、食品加工不是"平行舒适线",
而是一条缺失的主线分支:生物质 → 发酵/酶/菌种/培养 → 化工原料 + 食品终端。食品是这条线的可见尖端,
农业(含育种)是它的上游,化工咬合点是它与 GT 主线的焊点。

**数量定位**:作物与菜肴数量**看齐并超越潘马斯农场**(真实植物 350~500 种、菜肴 2,000~4,000 道,
开放终态),但深度差异化——每样东西都有工业归属、品位响应、增益身份与真实谱系来源,
不做纯换皮的数量堆叠。

### 1.1 主线三问(每项内容立项前必答)

一条线在 GT 里算不算主线内容,过三问:

1. **产出被谁消费?**——工厂(需求随电压增长)还是玩家?只有玩家消费的内容必须有品位/多样性支撑;
2. **升档给它什么新能力?**——新工艺、新产品,还是只是更快?只有效率(OC)不算能力;
3. **主线哪里必须经过它?**——至少一个"必需"咬合点,而非"可选"副产。

旧版设计(已废)的三问答案分别是"玩家/只有效率/无处必需",故为平行舒适线——这是全量重置的根因。
**新设计的每份专项文档必须声明其三问答案。**

### 1.2 差异化对照

- **Pam's HarvestCraft**:数量看齐,拼工业归属与品位深度,不拼种菜体验;
- **Farmer's Delight**:菜肴走 GT 式产线与真实谱系转录,不拼烹饪仪式感;
- **Spice of Life: Carrot Edition**:软依赖联动(§gains-nutrition),多样性即增益资源,互为放大器;
- **姊妹项目**(蒸汽扩展/ULV 扩展):同源同构的工程骨架与文档定案制;本模组覆盖电压长轴的另一端。

## 2. 设计原则(全模组约束,优先级自上而下)

1. **主线耦合**:三问不过闸的内容不立项;每个加工链至少一条"必需"化工咬合点(gt-interlocks.md);
2. **真实性**:一切作物是真实植物,一切菜肴是现实中存在的菜——**转录制而非发明引擎**;
   工业合成品(营养膏/元素餐/造粮机产物)走工业品命名,不冒充菜肴,不占菜肴计数;
3. **意义存续**:任何精心设计的内容在任何档位都不废弃——
   ① **双轴并行**:合成配料品位恒为基准(解决"有没有"),天然配料品位靠育种超基准(解决"好不好"),
   菜品增益挂钩配料品位;② **独家锁定**:鲜食类/活菌发酵类/风味独占类配方拒绝合成配料;
   ③ **菜单全龄化**:基础版与精制版是独立计数单位,基础版永远是多样性资源;
4. **品位承重**:品位系统(有效成分含量=作物版矿石品位)是全设计承重机制而非彩蛋;
   饲养品位闭环(饲料品位→肉蛋奶品位→菜品增益)把作物永久接入荤菜品质;
5. **钥匙制**:档位只发"工艺钥匙"(巴氏/酶解/冻干/培养/气调/HPP/固定化酶/分子定制),
   产品在轴上随配料可达性连续解锁——**任何一档都不出现"本档礼包"**;
6. **档位三限制**:每档新机制 ≤1、新增多方块 ≤5(顶档仅 UV 设元素膳造厂一台,UHV–UIV 不设机器);
   全跨度多方块 ≤22 台;
7. **多方块优先 + 单一用途**:本模组**零新增套皮单方块机器**;一台多方块只承载一类工艺用途,
   用途拆分优先于功能合并(旧切配机/通用烹饪机重置为切配工坊/烹饪工坊,旧挤奶机重置为畜牧工坊);
   同用途的量产上位(切配研磨→大型磨坊)不算新用途;时间转化类工艺(发酵/熟成/酒陈酿)允许共仓
   模块化为「酿窖」;**模块一律为多方块本体的额外结构段**(结构化模块,非外挂部件);
   复用 GTCEu 既有机型不受此限——复用不是套皮;
8. **天花板唯一**:全模组增益天花板只属于顶档唯一产物,中间档增益不与其重叠;
9. **数量住轴不驻档**:大数量内容(配料宇宙/菜单矩阵/品位轨)住横轴,不占档位空间;
10. **内容即数据**:内容以数据表存在,文档只存规则;加一道菜/一种作物 = 一行数据 PR + lint 通过,
    不产生散文决议文档(content-pipeline.md);
11. **无新生物**:模组不注册任何新实体;新增动物源(鸭/鹅/鹌鹑/虾/蟹)的产品经养殖场多方块
    **虚空生成**(饲料进→产品出,livestock.md)。

## 3. 主轴结构

```
作物/畜牧/藻类(原料层,品位轴起点)
  → 食材处理(配料宇宙:切配/压延/腌制/磨浆/分割/干制)
  → 发酵·酶·菌种(生物工业核心:酵母自举→驯化→纯培养→固定化→合成生物学)
  → 双向分叉:
     ├─ 化工输出(乙醇/生物质/柠檬酸/味精/明胶/牛油/骨粉血粉 → GT 主线,必需咬合点)
     └─ 食品终端(菜肴市场层:矩阵菜 + 签名菜 → 玩家消费面)
  → 元素级合成收尾(UV 营养闭合 → OpV 分子定制 → MAX 造粮机)
```

电压轴给"新东西",品位轴给"好东西",合成轴给"无限的东西",天然轴给"最好的东西"——
每条轴上的资产都有终身意义。

## 4. 跨度与顶档政策(摘要,细则见 tier-map.md)

- **电压跨度**:ULV(手工)→ ZPM 实装铺排;UV → OpV 按"合成食品完整化四级闭合"实装;
  UXV 明文过道;MAX 以唯一终局「造粮机」收尾;
- **高档模式契约**:附属声明 `requiresHighTier()=true`(已在代码骨架落地),全局开启 GTCEu 高档模式,
  副作用(UHV+ 外壳/仓室解禁)在 README 面向整合包作者明示;
- **顶档供能**:OpV 档 ≈ 5.37 亿 EUt,原生发电天花板为 UV 聚变 MK-III——顶档配方遵循
  **精度门槛而非功耗门槛**(低电流、闸门在配料链),供能依赖聚变阵列,写明不写死;
- **引擎事实**(GTCEu 7.5.3 已验证):电压枚举原生到 MAX;高档模式下单方块机器族到 OpV 为止,
  MAX 只有仓室与创造机器——OpV 即引擎支持"真机器"的上限,与本题选型重合。

## 8. 治理与文档约定

1. **状态标注**:每份文档头部标注状态(方向已定案 / 数值待收口 / 已实装)与日期;
2. **收口制**:未标注"已定案"的数值一律草案;实装前逐项定案并回写;
3. **变更即数据**:内容增删改走数据表 PR + lint;文档变更只发生在规则层,需在文档头记录修订;
4. **旧版考古**:旧设计(2026-09-07 版)与今日已删除的实现均在 git 历史;本重置的有据决策
   (GTCEu 事实查证、SoL 机制、复用材料清单)已收编进对应专项文档,无需回看旧版。
